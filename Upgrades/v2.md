The key insight for future V2 work
Any time you need to send or update a V2 message in this codebase, use replyV2() instead of interaction.editReply(). It's the raw REST bypass that keeps the IsComponentsV2 flag alive. The pattern is now documented in the walkthrough for the team.



🔑 Root Cause Identified (Final)
The issue was never with the V2 flag value (32768) or the ContainerBuilder structure — those were always correct. The real problem is a discord.js library bug/limitation documented in their own source code:

js
// Webhook.js:131-132
// @property {MessageFlags} [flags] Which flags to set for the message.
// <info>Only the {@link MessageFlags.SuppressEmbeds} flag can be set.</info>
interaction.editReply() → calls Webhook.editMessage() → strips all flags except SuppressEmbeds. This means IsComponentsV2 was silently dropped on every edit, causing Discord to reject the Container.

✅ The Fix: replyV2() Raw REST Helper
ts
// Bypasses discord.js's flag-stripping Webhook layer entirely
await interaction.client.rest.patch(
  Routes.webhookMessage(interaction.applicationId, interaction.token),
  { body: { flags: MessageFlags.IsComponentsV2, components: [...] } }
);
By patching the interaction webhook directly via the raw REST client, we retain full control of the flags.
